# 모바일 장바구니 변경으로 확인한 CI 검증 범위

## 실제 변경

[PR #15](https://github.com/heeji289/loop-pack-fe-l2-vol1/pull/15)에서 768px 이하의 장바구니 합계와 구매 버튼을 화면 하단에 고정했다. 기존 상태와 구매 이벤트를 재사용하며, safe-area와 고정 영역 높이만큼 목록 아래 공간을 확보했다. 좁은 화면의 상품 행은 줄바꿈하도록 했다.

정상 구현 커밋은 `405117d8`이다. 상품 8개를 담고 320×568·390×844·768×1024 및 데스크톱 1280×900에서 실제 Chromium 브라우저로 확인했다.

## 실험: 모바일에서 구매할 수 없어도 CI가 통과하는가

실험 커밋 `4e23fef7d3a1a2cd4871d71a20225617d4d6db92`에서 모바일 `.summary`에만 `transform: translateY(100%)`를 추가했다. API·테스트·CI 설정은 바꾸지 않았다.

390×844 viewport에서 구매 버튼은 y=868, 높이=48이었다. 화면 아래에 완전히 벗어나며 `click({ timeout: 1500 })`도 실패했다. 동일한 viewport 검사로 정상 구현과 결함 구현을 구분했다.

그런데 [실험 PR run 34446293956](https://github.com/heeji289/loop-pack-fe-l2-vol1/actions/runs/34446293956)은 성공했다.

| 검증 | 실제 결과 |
|---|---|
| 변경 판별 | CSS module 1개를 런타임으로, 스펙 Markdown 1개를 문서로 분류 |
| 단위 테스트 | 21개 파일·207개 테스트 통과 |
| 관련 통합 테스트 | 3개 파일·13개 테스트 통과 |
| lint·typecheck·production build | 통과 |
| 핵심 E2E | Desktop Chrome 3개 통과, flaky 0 |
| guard | 통과 |
| Production 배포 job | PR이므로 생략 |
| 동일 결함 코드의 로컬 전체 E2E | 5개 파일·16개 통과, flaky 0, 17.5초 |
| 별도 모바일 브라우저 검증 | 버튼이 viewport 밖에 있어 실패 |

선택된 통합 테스트는 `tests/cart-page.dom.test.tsx`, `tests/providers-restore.dom.test.tsx`, `tests/store-restore.dom.test.tsx`였다. CSS 변경의 관련 테스트 선택은 의도대로 작동했다.

전체 E2E 결과는 로컬에서 `pnpm build` 후 `CI=true pnpm test:e2e`로 확인한 것이다. PR에서 전체 E2E를 실행했다고 해석하지 않는다.

## 해석

이번에 발견한 공백은 테스트 선택 누락이 아니라 실행 환경과 검증 항목의 부재다. jsdom 테스트는 브라우저 레이아웃과 화면 밖 버튼을 검증하지 않으며, 현재 핵심·전체 E2E는 Desktop Chrome만 사용한다. 따라서 핵심 E2E를 전체 E2E로 확대하는 것만으로는 이 결함을 발견하지 못했다.

guard는 정해진 핵심 E2E가 실행·성공했음을 올바르게 확인했다. guard의 실행 조건 재계산은 테스트가 다루지 않는 모바일 레이아웃까지 보장하지 않는다.

후속 보완은 모바일 viewport에서 구매 버튼이 화면 안에 있고 실제로 주문서에 진입할 수 있는지를 검증하는 것이다. 이 PR은 기존 CI의 범위를 관찰하기 위해 CI 설정과 테스트 프로젝트를 유지했다.

## 정상 코드 복구

실험용 transform과 주석을 제거했고, CSS는 정상 구현 `405117d8`과 같아졌다. 복구 후 같은 모바일 검증을 다시 통과했다.

| viewport | 정상 버튼 y / 높이 | 결과 |
|---|---|---|
| 320×568 | 496 / 48 | 화면 안·가로 넘침 없음·마지막 상품 접근 가능 |
| 390×844 | 772 / 48 | 화면 안·가로 넘침 없음·마지막 상품 접근 가능 |
| 768×1024 | 952 / 48 | 화면 안·가로 넘침 없음·마지막 상품 접근 가능 |

전체 선택 해제 시 구매 비활성화, 로그인 안내가 구매 영역 위에 표시되는 동작, 로그인 후 모바일 구매 버튼으로 주문서 진입, 빈 장바구니의 구매 영역 미표시도 확인했다. 데스크톱 주문 요약은 기존 sticky 배치를 유지했다.

실기기 Safari와 실제 safe-area 크기는 이번 Chromium viewport 실험에 포함하지 않았다. 복구 커밋의 PR required checks 결과는 완료 후 기록한다. 이 실험으로 PR을 병합하거나 Production에 결함을 배포하지 않았다.
