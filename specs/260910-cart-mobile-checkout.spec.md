# 모바일 장바구니 구매 영역과 CI 검증 스펙

## 목표

모바일 장바구니에서 총금액과 구매 버튼을 화면 하단에 고정한다. 사용자가 승인한 실제 변경 실험으로, 모바일에서만 발생하는 CSS 결함을 기존 데스크톱 CI가 발견하는지도 PR에서 확인한다.

## 조사 결과

- `CartPage.module.css`의 768px 이하 분기는 현재 주문 요약을 목록 아래에 배치한다.
- 총금액·구매 가능 여부·로그인 안내·주문서 진입은 `CartPage.tsx`에 구현되어 있다. 이 상태와 이벤트를 재사용한다.
- Playwright 프로젝트는 Desktop Chrome 하나이며 모바일 viewport 전환은 없다.
- 이 CSS module은 통합 테스트 import 그래프에 포함된다. PR에서는 관련 통합 테스트와 핵심 E2E가 실행될 것으로 예상한다.

## 결정 사항

- 768px 이하에서 합계와 기존 구매 버튼을 하단 고정 영역으로 배치하고 safe-area 여백을 둔다.
- 마지막 상품을 가리지 않도록 목록 아래 공간을 확보한다. 좁은 화면에서 상품 행이 가로로 넘치지 않게 한다.
- 빈 장바구니에는 구매 영역을 표시하지 않는다. 선택 해제·가격 로딩/오류·로그인 안내의 기존 동작을 유지한다.
- 데스크톱 주문 요약은 현재 배치를 유지한다. 새 의존성·CI 설정·모바일 프로젝트는 추가하지 않는다.
- 정상 구현을 브라우저에서 확인한 뒤, PR에 모바일 구매 영역을 화면 밖으로 밀어내는 임시 CSS 결함을 넣어 CI 결과와 모바일 실패를 대조한다. 이 실험 커밋은 병합하지 않고 정상 코드로 복구한다.
- 최종 PR은 정상 구현과 실험 근거를 담고 최신 SHA의 required checks를 통과해야 한다. 병합·Production 배포는 이번 요청에 포함하지 않는다.

## 완료 조건

- [x] 320px·390px·768px 화면에서 구매 영역이 viewport 안에 있고 마지막 상품까지 조작할 수 있다.
- [x] 선택 해제 시 구매 버튼이 비활성화되고, 비로그인 구매 시 로그인 안내가 고정 영역 위에 열린다.
- [x] 로그인 상태의 모바일 구매 버튼으로 주문서에 진입한다.
- [x] 데스크톱에서 기존 주문 요약과 구매 동작을 유지한다.
- [ ] 모바일 결함 커밋에서 모바일 실패와 PR CI 결과를 SHA·run URL로 기록한다.
- [ ] 결함을 제거한 최종 코드의 모바일 검증·lint·build·관련 테스트 및 PR required checks가 통과한다.

## 태스크

- T2: self-review·정적 검사·관련 테스트 후 커밋과 PR 생성.
- T3: 임시 모바일 결함으로 CI 범위 실증, 정상 코드 복구, 최종 CI 확인 및 근거 기록.
