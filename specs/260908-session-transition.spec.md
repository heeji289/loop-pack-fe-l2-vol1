# 세션 교체와 주문 완료 후처리 정리

## 목표와 승인 범위

사용자가 기술 설계를 다시 검토하고 에이전트가 타당하다고 판단하는 방향으로 수정하도록 위임했다. 기존 세션 Query 전환 설계를 유지하면서, 로그인·로그아웃·만료의 캐시 교체 절차를 통일하고 만료 이후 늦은 주문 성공이 로그인 이동을 덮지 않게 한다.

## 조사 결과

- `replaceSessionUser`는 사용자 조회만 취소하며, 계정 조회 취소·제거는 각 호출자가 따로 수행한다.
- 만료 콜백은 사용자 교체 완료를 기다리지 않고 이동한다. 기존 중복 방지 플래그는 보호 화면의 이동만 막는다.
- `OrderForm`은 성공한 주문의 장바구니·draft 정리와 주문 내역 이동을 조건 없이 함께 수행한다.

## 결정 사항

- 기존 `replaceSessionUser`에서 사용자·계정 조회를 함께 취소하고 계정 캐시를 제거한 뒤 사용자를 기록한다. 계정 대상은 기존 `meta.requiresAuth`로 골라 도메인 간 import를 추가하지 않는다.
- 만료 처리는 교체 완료 후 이동한다. 진행 중 중복 처리를 막되, 공개 화면에서는 완료 후 다음 만료를 다시 처리할 수 있다.
- 주문 요청 시작 시 계정 ID를 기록한다. 성공한 주문의 장바구니·draft 정리는 유지하되, 현재 계정이 요청 계정과 다르거나 비로그인이면 주문 조회 갱신·주문 내역 이동은 하지 않는다.
- 문서 이동, 브라우저 주문 조회, 기존 AbortSignal 생략, 분석 식별 정책은 유지한다.

## 비범위

- 탭 간 동기화, 주문 API의 멱등성 보장, 결과를 받지 못한 주문의 복구 설계
- 외부 의존성·환경설정 변경

- [x] 교체로 취소된 사용자·계정 조회의 늦은 응답이 새 세션을 덮지 않는다.
- [x] 동시 만료는 한 번만 이동하며, 공개 화면에서 처리 후 다음 만료도 처리한다.
